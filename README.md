# Breltz Return Radar

Prototype and process write-up for the Hawky.ai Product Manager / FDE assignment.

**Live prototype:** enable GitHub Pages (Settings > Pages > Deploy from branch `main`, folder `/root`). `index.html` is a single self-contained file, so it also opens by double-clicking it.

**Process one-pager:** [docs/one-pager.md](docs/one-pager.md)

## The idea in brief
Breltz (D2C backpacks, 30% blended returns, contribution margin 22% to 9%) does not mainly have a quality problem: 75-80% of returned Commuters are grade A. It has an expectation gap created by ads and listings, and no data that shows it. Return Radar joins order, ad, return, ticket and QC data, then:

1. shows net ROAS per creative after returns,
2. audits ad and listing claims against the product master,
3. flags orders at risk of return for an early save,
4. replaces the return-reason dropdown with a structured two-tap flow.

All numbers in the prototype are illustrative placeholders based on the 26 Nov discovery call.
